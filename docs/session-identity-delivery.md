# 同项目多会话识别交付记录

日期：2026-10-26。目标固件：`2026.10.26-codex.5` 。

## 实现

工作页采用“小字项目名及固定编号、大字会话标题”的层级。模型、思考强度、上下文、工作阶段、工具、计划、耗时及待回答提醒继续同屏展示，按钮操作保持原有行为。短编号与右上角浏览序号分开，切换顺序不再影响会话身份辨识。

标题只读查询 Codex 本机 SQLite 会话索引，每 30 秒检查一次，即使日志没有新增也能发现改名。无标题或索引不可用时显示“未命名会话”，不生成虚构名称。内部审批会话沿用原有过滤逻辑。

短编号从完整会话 ID 派生，以 4 位开始，检测重复后给新编号加长，最长 12 位；分配结果保存在 daemon 状态目录的身份映射中，正常重启不会重排。跨轮次继续保留标题和编号。该映射只保存会话 ID 与编号。

工作协议增加 `0x66` 条目，继续接收旧 `0x62` 与 `0x65` 条目。每帧不超过 244 字节；标题使用原有字段之后的剩余空间，最多 144 字节，并按 UTF-8 字符边界截断。设备回读包含标题和短编号；完整标题保留在主机状态中。

## 侧边栏名称来源修正

用户发现屏幕显示首条消息而非侧边栏名称。实查确认：当前 Codex 将侧边栏名称保存于 `threads.name`，原实现误读了保存首条消息的 `threads.title`。现优先读取非空 `name`，无名称或旧版本缺少字段时兼容回退 `title`。

95 项主机测试通过，覆盖名称优先级、无新日志时改名更新和旧索引兼容。真实采集已核对截图中的“评估福利看板指标数据支持”和“更新假期看板进展与待办”完全一致。后台服务重启后，设备回读当前会话名称“改造 BLE 项目为 Codex 版本”，固定编号仍为 `6F55`；主机另一活跃会话名称为“更新假期看板进展与待办”，编号仍为 `AB59`。本修正无需重新刷写固件。
