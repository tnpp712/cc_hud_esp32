## 实现范围

| 功能 | 实际行为 |
|---|---|
| 紧凑排版 | 模型、强度、上下文已用比例合成一行；标题最多两行，常见中文标题均分换行，超长省略 |
| 具体进展 | 显示公开进度消息，普通进展最多每 5 秒切换；实际工具阶段、结构化计划独立保留，不采集推理内容 |
| 稳定切换 | 自动详情至少停留 8 秒；待处理优先；手动选定保持到再次短按，选中会话消失时退回总览 |
| 待处理卡 | 显示精确问题 ID 对应的未答问题标题，部分回答切换到下一问题；人工审批使用操作说明，自动审批不提醒 |
| 完成卡 | 显示公开最终回复摘要、耗时和有结构化证据的文件／测试命令统计，区分本轮结束、中断和失败；自动展示 20 秒，手动选择或待处理优先 |
| 结果回看 | 当前 daemon 运行期间保留最近 3 条结果、最长 30 分钟；新轮次可与上一轮结果同时浏览，结果不增加忙碌计数 |
| 多会话总览 | 每页 4 条，显示状态、项目名、会话标题；协议最多 8 条，当前会话优先占用名额 |
| 灯效 | 柔和青绿工作灯、琥珀待处理呼吸、明确错误红闪；全部空闲后单次绿脉冲，同轮重复结束不重复提示；7D 余量继续由空闲灯环表达 |

首次短按进入总览；继续短按依次浏览总览分页、会话详情、结果和时钟；时钟再短按回到自动总览。长按仍调暗／恢复。手动浏览时，全局待处理徽标和灯效仍提供提示。

## 数据和协议边界

公开进度读取 `response_item` 中助手消息的 `commentary`，最终摘要读取 `final_answer`；`analysis` 等其它阶段不进入展示。没有结构化计划时不估算完成百分比。最终回复是结果摘要来源，不是新增的独立业务验收证据。

只有成功 `FileChange` 才统计文件数；只有带明确退出码的结构化 `CommandExecution` 才统计识别到的测试命令成功次数，不把工具调用次数当测试数，不把自然语言中的“测试通过”当结构化证据。

新增 `0x67` 卡片分片。新条目需基础信息和三类文字分片全部到齐才发布；旧条目继续按旧规则接收。每个 BLE 帧不超过 244 字节，文字按 UTF-8 边界限制。卡片回读使用新增只读特征 `12345678-aaaa-bbbb-cccc-1234567890a5`，项目和工作元数据仍使用原 `a4` 特征。扩大的显示模型放在静态区，避免挤占 Arduino 任务栈。

## 首次升级与写入断连定位

用户重启后，首版 `.8` BLE OTA 传输 2723376 字节，耗时 930.8 秒，收到最终 `OK`，版本回读确认启动 `.8`。随后验收在首次额度写入时断连；重连后，独立发送 5 字节的旧状态帧也复现断连，因此首次真机验收未通过，不能仅凭 OTA 完成认定交付成功。

编译产物反汇编确认，`QuotaCallbacks::onWrite` 的栈帧为 `0x640`，即 1600 字节；蓝牙任务栈默认为 4096 字节。扩展的解析结构会使任何写入分支承担这个栈帧。将串行回调使用的大解析结构改为静态缓冲后，栈帧降至 `0x160`，即 352 字节；同时把蓝牙任务栈增加到 8192 字节。此为针对已复现写入失败的修复，仍需再次真机验收验证。

新增只读健康特征 `12345678-aaaa-bbbb-cccc-1234567890a6`，回读运行时长、重启原因、空闲堆和任务栈余量，便于后续稳定性排查，不在屏幕展示这些内部字段。

修复版 `.9` 已通过 17 项 native 回归和 ESP32-S3 构建，固件文件 2725104 字节，SHA-256 为 `30c58f40d3ed1c1a8aafd5d20fc6a4a26102f1b0c68c6610c3def85fb30e0a47`。修复版最终验收结果见下文。
