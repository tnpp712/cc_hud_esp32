# Codex HUD 改造与验收

日期：2026-10-23。

本文保留各轮迁移历史。工作页当前实现见 [工作页交付记录](work-page-delivery.md) ，待回答、思考强度和上下文显示的最新状态见 [本轮交付记录](input-context-delivery.md) 。后续记录优先于本文中的早期排查结论。

## 改造范围

固件默认品牌改为 Codex，BLE 广播名为 `Codex-HUD` 。使用自绘终端图标、光标动画、统一工具图标、青绿色强调色与中文文案；四页布局、状态优先级和省电机制保留。5H 额度、重置倒计时、阈值告警、耗尽预测以及灯环 / 宠物对 5H 的依赖均已移除，统计页改为 7D 重置倒计时。网页面板同步改版。

主机增加 Codex 本地日志增量用量采集，状态通过 Codex hooks 上报。新 hooks 覆盖开始、工具前后、审批、结束、中断及会话关闭。完成脉冲只在所有会话空闲时触发。

| 指标 | 来源及边界 |
|---|---|
| 7D 额度 | `token_count.rate_limits`，只识别 10080 分钟窗口，忽略 5H，不按 primary / secondary 位置猜测 |
| 上下文 | 最近请求 token 数 / 当前上下文窗口，不使用累计 token 数 |
| 时长 | 当前轮次开始到最近用量事件的时长 |
| 增删行 | 成功 `FileChange` 的累计修改行数，不覆盖 shell 或外部编辑器写入 |
| 费用 | Codex 订阅日志没有实际美元账单，显示未提供；通用协议费用推送保留 |
| 缺失数据 | v7 `0x0C` 指标有效位控制未知显示，防止旧 Claude 数据或假零值残留 |

## 自动审批红灯误报修复

已采到当前会话的真实 `PermissionRequest`：hook 中 `permission_mode=default`，而同轮 `turn_context.approvals_reviewer=auto_review`。旧逻辑仅排除 `bypassPermissions`，把该事件误报为人工等待，导致没有用户确认框时短暂红闪。

本次改动：

- hook 继续只透传必要元数据，补充 `turn_id` 与 `transcript_path`。
- 适配器仅在 `CODEX_HOME/sessions` 内逆向读取匹配轮次的审批处理方，最多读取 8 MiB，不输出提示词或工具正文。
- `auto_review` 按工作状态处理；人工审批保持等待状态。元数据缺失时保留原有行为，并记录处理方未知。
- 临时采样逻辑已移除，没有修改任何信任记录或审批决策。

验证：63 项主机测试通过。已重启当前仓库的 daemon；实际自动审批事件日志回读为 `处理方=auto_review，HUD状态=工作`，BLE 已重新连接。无需更新固件。

本次成功采到当前会话的自动 hook 事件，说明当前自动触发链路已经工作；此前“旧会话可能未加载新配置”的推测不能继续作为当前状态的解释。
